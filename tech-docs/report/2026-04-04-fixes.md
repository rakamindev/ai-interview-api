## 1. Browser mic stuck muted after Gemini unexpected close

**Problem:** When Gemini disconnected unexpectedly (e.g., 1008) during AI speech, `state.model_speaking` was cleared server-side but no `speaker_changed:candidate` was sent to the browser. The frontend mic stayed muted forever — the retry reconnected, but the candidate couldn't speak.

**Fix:** In `handle_gemini_close`, send `speaker_changed:candidate` to the browser when `model_speaking` was true at the time of the close.

**File:** `audio_websocket_middleware.rb` — `handle_gemini_close`

---

## 2. Coverage probe count inflated (7 probes after 4 turns)

**Problem:** The coverage analyzer runs once per candidate turn with a sliding 6-turn window. Consecutive runs share 5 of 6 turns, so Flash double-counted overlapping exchanges and inflated `probe_count` far beyond the actual number of exchanges.

**Fix:** Cap `probe_count` increment at +1 per analyzer run. Applied before the `StateEngine` gate check so state advancement also uses the correct count.

**File:** `app/services/coverage/analyzer.rb` — `parse_skill_updates`

---

## 3. Covered skills keep getting probed (probe_count keeps rising)

**Problem:** After a skill reached `covered` state, Flash still saw old turns about it in the sliding window and kept incrementing its `probe_count`. The AI also kept discussing covered skills instead of moving on.

**Fix:** Skip updates entirely for skills already at `covered` state — freeze their `probe_count`.

**File:** `app/services/coverage/analyzer.rb` — `parse_skill_updates`

---

## 4. `advance_stale_partials` auto-advancing too aggressively

**Problem:** The `advance_stale_partials` method auto-promoted any `partial` skill with `probe_count >= 2` to `covered` — including skills that were just set to `partial` in the same analyzer run. A skill could go `not_yet → initiated → partial → covered` in 2 turns.

**Fix:**
- Raised threshold from `probe_count >= 2` to `probe_count >= 4`.
- Excluded skills updated in the current worker run (`exclude_ids` parameter) so freshly-promoted skills aren't immediately auto-advanced.

**File:** `app/workers/coverage_analyzer_worker.rb` — `advance_stale_partials`

---

## 5. `check_session_end_conditions` used `.none?` instead of `!exists?`

**Problem:** ActiveRecord's `.none?` on a relation without a block can behave unexpectedly. Combined with a stale `session.ended?` check (no reload), the auto-end detection could silently fail.

**Fix:** Changed to `!exists?` (explicit SQL EXISTS query) and added `session.reload.ended?`.

**File:** `app/workers/coverage_analyzer_worker.rb` — `check_session_end_conditions` (later removed entirely)

---

## 6. Coverage auto-end used wrong reason string

**Problem:** `check_coverage_complete` passed `reason: 'coverage_complete'` to `EndHandler`, but `coverage_complete` is not in `Session::END_REASONS`. The fallback silently converted it to `manual_assessor`, making auto-ends look like manual assessor actions in logs/DB.

**Fix:** Changed to `reason: 'all_covered'` (which is in `END_REASONS`). Later, the entire coverage auto-end was disabled (see #7).

**File:** `audio_websocket_middleware.rb` — `check_coverage_complete`

---

## 7. Coverage auto-end disabled (moved to backlog)

**Problem:** The auto-end logic only checked configured skills (`is_discovered: false`). Discovered skills were ignored — the session would end while the AI was actively probing discovered skills. Additionally, timing issues caused the AI to be cut off mid-sentence.

**Fix:** Removed `check_coverage_complete` entirely. Session now only ends via manual action (candidate/assessor) or time ceiling. Coverage auto-end is in the backlog pending discovered skill probing limits and two-phase wrap-up implementation.

**File:** `audio_websocket_middleware.rb`

---

## 8. Full reconnect: AI re-asks the same question in a loop

**Problem:** When Gemini's resumption token expired, a full reconnect injected conversation history via `inject_context` with `turnComplete: true`. If the AI's question was the last thing in history, Gemini re-asked it. The candidate's audio was forwarded but not transcribed, and the AI kept looping the same question.

**Fix:**
- Added `turn_complete:` parameter to `inject_context` (defaults to `true`).
- When last speaker was AI: inject history with `turn_complete: false` so Gemini treats it as context without re-asking. The candidate's audio naturally completes the open turn via VAD.
- When last speaker was candidate: use `turn_complete: true` to prompt AI to continue.
- Gate candidate mic (`model_speaking = true`) before injection to prevent audio collision.

**Files:** `live_client.rb` — `inject_context`, `audio_websocket_middleware.rb` — `restore_conversation_context`

---

## 9. Empty generationComplete adds unnecessary 0.8s delay

**Problem:** Coverage injection with `turnComplete: true` sometimes caused Gemini to generate an empty response (0 audio chunks). The 0.8s `GATE_OPEN_DELAY` timer still fired, adding delay before the real AI response could start.

**Fix:** Track whether audio was actually emitted during the generation. If `emitted_audio = false`, skip the gate delay entirely — no speaker output to drain, no echo risk.

**File:** `live_client.rb` — `generationComplete` handler

---

## 10. Coverage injection silently dropped (return value not checked)

**Problem:** The middleware called `inject_context` for coverage but didn't check the return value. When the injection was skipped (silence pump active or model emitting), the middleware still set `last_injected_digest`, marking it as done. Coverage was never retried on subsequent turns.

**Fix:** Only set `last_injected_digest` when `inject_context` returns `true` (actually sent). If skipped, the digest stays stale and injection is retried next turn.

**File:** `audio_websocket_middleware.rb` — `on_input_transcription` callback

---

## 11. Event log missing `inputTx=` / `outputTx=` (wrong dig path)

**Problem:** The diagnostic event log checked `sc.dig('inputTranscription', 'parts', 0, 'text')` but Gemini sometimes puts transcription text directly at `inputTranscription['text']` (no `parts` array). The log never showed `inputTx=` even when transcription was working.

**Fix:** Added fallback: `|| sc.dig('inputTranscription', 'text')` to match the same fallback used in the actual transcription handler.

**File:** `live_client.rb` — `log_gemini_event`

---

## 12. System prompt: AI mentions skill names during transitions

**Problem:** The AI would say things like "We've discussed a lot about problem solving and learning" when transitioning between topics. The candidate should not know which skills are being assessed.

**Fix:** Strengthened rule 6 (Natural Transitions) in the system prompt to explicitly say "Never mention skill names, topic names, or summarize what was already covered."

**File:** `app/services/assessments/system_prompt_compiler.rb`

---

## 13. System prompt: AI asks follow-up questions during wrap-up

**Problem:** When the AI received a wrap-up signal, it would ask "Do you have any questions about the role?" instead of delivering a clean closing statement. This extended the session unnecessarily.

**Fix:** Updated rule 7 (Wrap Up) to say "Do NOT ask follow-up questions. Keep it short and natural — one closing statement, then stop."

**File:** `app/services/assessments/system_prompt_compiler.rb`
